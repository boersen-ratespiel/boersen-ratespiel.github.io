# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Börsen-Ratespiel — News, Wissen, ein Ratespiel und ein Musterdepot rund um die Börse, alles simuliert und ohne Risiko. Reines Vanilla HTML/CSS/JS ohne Build-Step und ohne Abhängigkeiten. Als installierbare PWA nutzbar (siehe unten).

## Running

Einfach `index.html` im Browser öffnen. Kein Build, kein Package-Manager, keine Tests vorhanden.

## Architecture

Die Single-Page-App (`index.html` + `style.css` + `script.js`) ist der Kern, dazu kommen PWA-Dateien und zwei rechtliche Standalone-Seiten:

- `index.html` — Seitenstruktur: ein Menü (`#menu`) zur Auswahl, plus je eine `<section class="view">` pro Feature (`#daily-view`, `#lernpfad-view`, `#news-view`, `#learn-view`, `#game-view`, `#depot-view`, `#sparplan-view`, `#lexikon-view`, `#erfolge-view`, `#broker-view`)
- `style.css` — Theme via CSS-Variablen in `:root` (Farben für bg/panel/text/green/red/accent), Glassmorphism-Look (Blur, halbtransparente Panels), lokal gehostete Schriftart "Outfit" (siehe PWA-Abschnitt)
- `script.js` — Navigations-Logik + gesamte Spiellogik
- `manifest.json`, `sw.js`, `icons/`, `apple-touch-icon.png`, `favicon.png`, `fonts/` — PWA-Infrastruktur
- `news.json`, `termine.json`, `scripts/update_news.py`, `scripts/update_termine.py`, `.github/workflows/update-news.yml` — automatisch aktualisierte News und Termine (siehe Abschnitt News)
- `scripts/build_lexikon.py` — erzeugt beim Deploy die Lexikon-Einzelseiten `lexikon/*.html` und `sitemap.xml` (siehe Lexikon)
- `scripts/build_tiktok.py`, `scripts/tiktok/render.html`, `scripts/tiktok_post.py`, `scripts/tiktok_auth.py`, `.github/workflows/tiktok-post.yml` — täglicher, selbst gezeichneter TikTok-Beitrag (siehe TikTok)
- `impressum.html`, `datenschutz.html` — eigenständige Seiten (kein Teil der SPA-Navigation, verlinkt aus dem `.app-footer` in `index.html`), teilen sich aber `style.css` für den gleichen Look

**Navigation:** Die App startet auf dem Menü (`#menu`). Ein Klick auf einen `.menu-item[data-view]`-Button ruft `openView(viewId)` auf: Menü aus, passende `.view`-Section ein (per `hidden`-Klasse), bereichsspezifischer Start (Quiz zurücksetzen, Spielrunde starten, Tages-Challenge laden, Sparplan rechnen …). Der `.back-btn` in jeder View ruft `closeView()` auf. Beim Verlassen einer Ansicht stoppt `leaveView()` deren Timer (Depot-Live, Rundentimer) — auch wenn man über einen Querverweis direkt in eine andere Ansicht springt. Neue Features bekommen eine weitere `.view`-Section plus einen Menüpunkt.

**Direktlinks:** Jede View trägt `data-hash` (`challenge`, `lernpfad`, `news`, `lernen`, `spiel`, `depot`, `sparplan`, `lexikon`, `erfolge`, `broker`). `openView()` setzt den Hash per `history.replaceState` (kein neuer History-Eintrag), `closeView()` entfernt ihn. Beim Laden öffnet die Zeile `initialView` (unten in `script.js`, nach allen Definitionen) die passende View — so führt der geteilte Link `https://boersen-ratespiel.github.io/#challenge` direkt in die Tages-Challenge.

**Querverweise:** Ein globaler Klick-Handler reagiert auf `[data-goto="<view-id>"]` (öffnet eine Ansicht) und `[data-lex="<id>"]` (öffnet den Lexikon-Eintrag `#lex-<id>`). Im Fließtext sind das `<a class="link-btn" href="#…">` statt `<button>` — Chrome rendert Buttons immer als inline-block, dann bricht ein Satzzeichen hinter dem Link allein in die nächste Zeile. `openLexikon()` merkt sich in `lexReturnView`, aus welcher Ansicht man kam; „Zurück" im Lexikon führt dorthin zurück (z. B. mitten ins laufende Quiz), nicht ins Menü.

**Spielablauf in `script.js`** (Section `#game-view`):

1. `generateSeries()` erzeugt einen Kursverlauf als Random Walk mit Drift + Volatilität (Gaussian-verteilte Schocks über `gaussianRandom()`, Box-Muller-Transformation). Insgesamt `HISTORY_POINTS` (90) sichtbare Vergangenheitspunkte + `FUTURE_POINTS` (25) verdeckte Zukunftspunkte.
2. `draw(visibleCount, opts)` rendert den Verlauf auf dem `<canvas>` per 2D-Context — Gradient-Fläche + Glow unter/um die Linie, Vergangenheit in Blau, aufgedeckte Zukunft farbig je nach Ergebnis (grün/rot), getrennt durch eine gestrichelte Linie bei `HISTORY_POINTS`.
3. `newRound()` startet zusätzlich `startRoundTimer()` — ein `ROUND_TIME_MS` (6s) Countdown mit visueller Leiste (`#roundTimerBar`). Läuft die Zeit ab, wird die Runde automatisch als falsch gewertet (`revealAndScore(null, true)` — `null` kann nie `=== true/false` sein, daher immer `correct === false`).
4. Klick auf „Rauf“/„Runter“ triggert `revealAndScore()`, das den Timer stoppt und den Rest der Serie per `setInterval` (40ms/Frame) animiert aufdeckt, dann `showResult()` aufruft.
5. `showResult()` wertet Treffer/Serie/Bestserie aus. Punkte pro Treffer = `BASE_POINTS` (10) × Multiplikator aus `getMultiplier(streak)` (1× / 1.5× ab Serie 3 / 2× ab Serie 5 / 3× ab Serie 10, angezeigt als Badge). Bei Erreichen einer Serie aus `STREAK_MILESTONES` erscheint ein kurzer Toast (`showStreakToast()`). Bei Treffer zusätzlich `burstConfetti()`. Die Bestserie (`best`) wird in `localStorage` unter dem Key `boersenspiel_best` persistiert.

Wichtig: `newRound()`/der Rundentimer werden NICHT beim Laden der Seite gestartet, sondern erst wenn `#game-view` über das Menü geöffnet wird (`if (btn.dataset.view === 'game-view') newRound();` im Menü-Click-Handler oben in der Datei) — sonst würde der 6s-Timer schon unsichtbar im Hintergrund laufen, bevor der Nutzer das Spiel überhaupt sieht, und beim ersten Blick wäre die Runde eventuell schon durch Zeitablauf verloren. Verlassen der Ansicht über `.back-btn` stoppt den Timer über `clearRoundTimer()`.

**Tages-Challenge (`#daily-view`):** Wordle-Prinzip für das Ratespiel. Jeden Tag `DAILY_ROUNDS` (5) Kursverläufe, für alle Spieler gleich, kein Timer, ein Versuch pro Tag. Der Tag ist der Kalendertag in Berlin (`berlinDayKey()`, via `Intl.DateTimeFormat` mit `timeZone: 'Europe/Berlin'`), die Challenge-Nummer zählt ab `DAILY_FIRST_DAY` (2026-09-27 = #1). `dailySeriesFor(tag, runde)` ruft denselben `generateSeries()` wie das freie Spiel auf, aber mit festem Seed (`hashString` = FNV-1a → `mulberry32`) und einer Normalverteilung per Irwin-Hall (Summe aus 12 Gleichverteilungen − 6) statt Box-Muller: `Math.log`/`Math.cos` dürfen je nach Browser-Engine in der letzten Stelle abweichen, Grundrechenarten nicht — sonst könnten zwei Spieler minimal andere Kurven sehen. **Seed-String, Generator oder `generateSeries()` nie ändern, ohne zu bedenken, dass sich damit die Challenge des laufenden Tages für alle ändert.** Jeder Tipp wird sofort (vor der Animation) unter `localStorage`-Key `boersenspiel_daily` gespeichert (`{date, results, streakDays, lastCompleted}`), damit Neuladen keinen zweiten Versuch ergibt; halb gespielte Challenges werden fortgesetzt. `streakDays` zählt Tage in Folge und verfällt, wenn gestern nicht abgeschlossen wurde. „📤 Ergebnis teilen" nutzt `navigator.share` (Handy) bzw. die Zwischenablage, Text aus `dailyShareText()`; GoatCounter zählt Klicks als Event `daily-share`. Der Menüpunkt zeigt über `updateDailyMenuLabel()` den heutigen Stand. Unter dem Ergebnis steht eine Statistik wie bei Wordle (`renderDailyStatsPanel()`: gespielt, Ø Treffer, Serie, beste Serie, Treffer-Verteilung) aus `history` (`{datum: treffer}`) und `maxStreak` im selben Storage-Objekt. „🖼️ Als Bild teilen" zeichnet per `drawDailyShareImage()` ein 1080×1080-PNG (Kästchen als gezeichnete Formen, nicht als Emoji — Emojis fehlen je nach Gerät im Canvas) und teilt es über `navigator.share({files})`, am Desktop als Download.

**Erfolge (`#erfolge-view`):** 17 Abzeichen in `BADGES` (oben in `script.js`, direkt nach der Navigation — die Bereiche weiter unten rufen `unlockBadge(id)` auf, die Konstanten müssen dann schon initialisiert sein). Gespeichert unter `localStorage`-Key `boersenspiel_badges` (`{earned: {id: datum}, lexRead: [...], quizDone: [...]}`); `markProgress('lex'|'quiz', wert)` merkt sich gelesene Lexikon-Einträge (über `openLexikon()`) und abgeschlossene/fehlerfreie Quiz-Level (`'leicht'`, `'perfect:leicht'`). Neue Erfolge erscheinen als Toast `#badgeToast`; gleichzeitig freigeschaltete werden zu einer Meldung zusammengefasst. Neues Abzeichen: Eintrag in `BADGES` + `unlockBadge()` an der passenden Stelle.

**Lernpfad (`#lernpfad-view`):** Sechs Schritte in `LERNPFAD_STEPS`, jeder mit einer `done()`-Prüfung auf Erfolge/Fortschritt (Lexikon „aktie"/„etf" gelesen, Quiz „leicht" beendet, Sparplan-Rechner geöffnet, erste Aktie gekauft, Challenge gespielt). `renderLernpfad()` läuft nach jedem freigeschalteten Erfolg neu und vergibt am Ende selbst das Abzeichen `lernpfad_done`.

**News (`#news-view`):** Echte Wirtschaftsmeldungen aus zwei frei nutzbaren Quellen. `scripts/update_news.py` (nur Python-Stdlib) holt die RSS-Feeds des **Statistischen Bundesamts** (`Aktuell.xml`, deutsch, mit Kurztext, gefiltert auf wirtschaftsrelevante Themen über `RELEVANT`) und der **EZB** (`press.xml`, englisch, nur Titel, nur Pressemitteilungen unter `/press/pr/` — Reden/Interviews tragen Autorennamen und haben strengere Regeln), kürzt die Kurztexte (`TEASER_MAX_CHARS`), leitet Thema (`CATEGORIES`), Relevanz (`HIGH_IMPACT`/`MID_IMPACT`, 1-3 Flammen) und die **Richtung der gemeldeten Zahl** (`trend`: up/down/flat, aus Vorzeichen wie "+4,6 %" und Signalwörtern) ab und schreibt `news.json` (max. 24 Meldungen, nicht älter als 14 Tage). Die Datei wird nur neu geschrieben, wenn sich die Meldungen geändert haben (kein Commit-Rauschen); scheitern alle Quellen, bleibt die alte Datei liegen und das Skript endet mit Exit 1. `.github/workflows/update-news.yml` führt das Skript stündlich (Minute 17) aus und committet `news.json` direkt auf den Standard-Branch (`permissions: contents: write`); nur wenn sich wirklich etwas geändert hat, ruft der zweite Job `deploy` anschließend `deploy-pages.yml` auf (siehe **Deployment**). Manuell auslösbar über Actions → "Update news" → Run workflow. Lokal testen: `python3 scripts/update_news.py`.

**Bewusst KEINE Bullish/Bearish-Bewertung bei echten News:** "Erzeugerpreise +4,6 %" ist weder gut noch schlecht für Anleger, sondern nur "die Zahl steigt" — eine Ampel würde in einer Lern-App Falsches beibringen. Deshalb tragen echte Meldungen `trend` (📈 Zahl steigt / 📉 Zahl sinkt / ⚪ Neutral, im Zweifel neutral). Nur die erfundenen Beispielmeldungen haben `sentiment` (bullish/bearish/neutral); `newsSignal(item)` in `script.js` wählt je nach Modus. Der Ein-Zeiler `renderNewsAiFazit()` ist im Live-Modus ein sachlicher "Überblick" ("Von 4 Meldungen zeigen 3 steigende Zahlen"), im Beispielmodus das alte "KI-Fazit".

Im Frontend (`script.js`, Abschnitt "News") lädt `loadNews()` `news.json` (`cache: 'no-cache'`), validiert jeden Eintrag in `parseNewsFeed()` (Link muss `https` und einer der Hosts in `NEWS_LINK_HOSTS` sein, alle Werte werden auf erlaubte Formen begrenzt, ungültige Einträge fliegen raus) und rendert **alle Fremdtexte nur über `escapeHtml()`** — nie ungeprüft in `innerHTML`. `renderNews()` zeigt 4 Meldungen pro Seite (die letzte Seite darf kürzer sein); die Top Story ist die relevanteste der Seite; "🔄 Weitere Meldungen" (`#newsShuffle`) blättert seitenweise. Jede Meldung zeigt Quelle, Alter ("vor 3 Std."), ein "EN"-Kennzeichen bei englischen Originalen (bewusst unübersetzt: die EZB verlangt korrekte Wiedergabe) und "Weiterlesen ↗". Der Ticker (`#tickerTrack`) zeigt bis zu `TICKER_MAX_ITEMS` Schlagzeilen; `updateTickerSpeed()` setzt die Animationsdauer aus der tatsächlichen Breite (konstant `TICKER_PX_PER_SECOND`). Das Ticker-Label kommt aus `data-label` (`📰 AKTUELL` bzw. `🧪 BEISPIEL`) via `content: attr(data-label)`.

**Ersatzmodus:** Kann `news.json` nicht geladen werden (und ist auch nichts im Service-Worker-Cache), zeigt die App `NEWS_EXAMPLES` (frei erfundene Meldungen) — dann aber bewusst gekennzeichnet: gelbes Banner `#newsStatus`, Ticker-Label "🧪 BEISPIEL", an jeder Karte "🧪 Beispielmeldung — frei erfunden". Erfundenes darf nie als echte Nachricht durchgehen.

**Termine der nächsten 7 Tage (`#terminePanel`, zwischen Top Story und Meldungen):** `scripts/update_termine.py` (nur Stdlib, importiert `RELEVANT`/`HIGH_IMPACT`/`contains`/`fetch` aus `update_news.py`) schreibt `termine.json` mit den Terminen der nächsten 14 Tage aus vier Kalendern: **Destatis-Wochenvorschau** (HTML-Tabelle, wird freitags 10 Uhr für die Folgewoche aktualisiert, gefiltert über `RELEVANT`, Uhrzeit laut Destatis "im Allgemeinen 8:00"), **BEA-iCal** (nur die Veröffentlichungen in `BEA_RELEASES`: BIP, Personal Income and Outlays/PCE, Außenhandel), **EZB-Sitzungskalender** (nur geldpolitische Sitzungen mit "followed by press conference" = Zinsentscheid) und **FOMC-Kalender der Fed** (letzter Sitzungstag, 14:00 Uhr Washington über `zoneinfo` nach Berlin umgerechnet — in den Wochen unterschiedlicher Zeitumstellung 19:00 statt 20:00). Läuft in derselben Action als eigener Schritt mit `continue-on-error`, damit ein Kalenderfehler die News nicht blockiert. Das Frontend (`loadTermine()`/`parseTermine()`/`renderTermine()` in `script.js`) validiert wie bei den News (Hosts in `TERMINE_LINK_HOSTS`, alles über `escapeHtml()`), zeigt nur heute bis +6 Tage, gruppiert nach Tag und sortiert selbst. Es gibt **keine erfundenen Ersatz-Termine**: fehlt `termine.json`, bleibt das Panel versteckt. Bewusst fehlen ifo, Einkaufsmanagerindizes (S&P Global), Uni-Michigan-Index, US-Arbeitsmarktdaten (BLS antwortet automatischen Abrufen mit 403) und Quartalszahlen — für diese gibt es keine frei nutzbare Quelle; die Fußnote des Panels sagt das offen. Nutzungsbedingungen (geprüft am 2026-09-22): BEA (https://www.bea.gov/help/faq/147) und Federal Reserve (https://www.federalreserve.gov/disclaimer.htm) sind Public Domain; Destatis und EZB wie unten. Der Titel "US-Notenbank (Fed): Zinsentscheid" ist von der App formuliert (Public Domain erlaubt das), EZB- und BEA-Titel bleiben englisch im Original, die 💡-Erklärungen (`hint`) und "⭐ wichtig" (`key`) kommen von der App und sind in der Fußnote so gekennzeichnet.

**Klassifikation ist bewusst simpel:** Thema/Relevanz/Richtung sind Schlagwort-Regeln im Skript, keine echte Analyse. Bei `contains()` gilt Teilstring-Treffer (deutsche Komposita: `preis` trifft "Erzeugerpreise"), ein `$` am Ende verlangt ein ganzes Wort (`bip$` trifft "BIP", nicht "Bipolar"). Die Richtung wird zuerst am Vorzeichen in der Überschrift erkannt, dann an Signalwörtern in Überschrift und erstem Satz; bei Widerspruch gilt `flat`.

**Lernen (`#learn-view`):** Multiple-Choice-Quiz mit drei Schwierigkeitsgraden (`LEVELS` in `script.js`: leicht/mittel/schwer, je 20 Fragen in `QUIZ_DATA`). Pro Durchlauf zieht `drawQuizQuestions()` `QUIZ_ROUND_SIZE` (10) zufällige Fragen und mischt die Antworten (`correct` wird dabei auf die neue Position umgerechnet — in `QUIZ_DATA` ist `correct` immer der Index in der Original-`options`-Liste). Das optionale Feld `lex` verweist auf einen Lexikon-Eintrag; nach der Antwort erscheint dann „📖 Mehr dazu im Lexikon". Fragen zu Steuern/Zahlen (Sparerpauschbetrag, DAX-Größe) bei Gesetzesänderungen aktualisieren. Ablauf: Level-Auswahl (`#learnLevels`) → Quiz (`#learnQuiz`, 3 Leben, Punkte je nach Level, Fortschrittsbalken) → Ergebnis (`#learnResult`, mit Konfetti bei perfektem Lauf). `resetLearnView()` setzt die Ansicht beim erneuten Öffnen über das Menü immer auf die Level-Auswahl zurück, egal in welchem Quiz-Zustand man vorher war. Highscores pro Level werden unter `localStorage`-Key `boersenspiel_learn_best` persistiert.

Achtung: `.result-panel` hat eine EIGENE Animation (`resultPopIn`) statt der `popIn`-Keyframe vom `.banner` — `popIn` enthält `translate(-50%,-50%)`, was nur für das absolut-positionierte, zentrierte Banner Sinn ergibt. Eine geteilte Animation zwischen beiden hatte das Ergebnis-Panel in die obere linke Ecke verschoben.

**Sparplan-Rechner (`#sparplan-view`):** Schieberegler für Sparrate, Startbetrag, Laufzeit und angenommene Rendite, dazu optional „in heutiger Kaufkraft" (`SP_INFLATION` = 2 % p. a.; abgezinst wird nur der Wert, die Einzahlungen bleiben nominal). `computeSparplan()` rechnet monatlich (Einzahlung zu Monatsbeginn, Monatszins = (1+r)^(1/12)−1), `drawSparplanChart()` zeichnet Einzahlungen (blau) und Wert (grün) aufs Canvas, dazu Zwischenstände alle 5 Jahre. Nichts wird gespeichert. Darunter ein zweiter Broker-CTA (gleiche Links wie im Depot, GoatCounter-Events `broker-*-sparplan`, ebenfalls als „Werbung" gekennzeichnet — beim Austausch der Affiliate-Links **beide Stellen** ändern).

**Börsen-Lexikon (`#lexikon-view`):** Die Einträge stehen bewusst als statisches HTML in `index.html` (`<article class="lex-entry" id="lex-<id>" data-match="…">`), nicht in JS — so sind sie für Suchmaschinen lesbar. Alphabetisch halten. `filterLexikon()` filtert per Volltextsuche. `data-match` sind kommagetrennte Schlagwörter nach denselben Regeln wie `contains()` in `update_news.py` (Teilstring, `$` am Ende = ganzes Wort); `renderNews()` sucht damit in Überschrift und Kurztext der angezeigten Meldungen und zeigt Treffer als Chips „📖 Begriffe erklärt" (`#newsTerms`). Leeres `data-match` = Eintrag wird in News nie vorgeschlagen (z. B. „Aktienindex", das sonst bei jedem „Verbraucherpreisindex" anschlagen würde).

**Lexikon-Einzelseiten (SEO):** `scripts/build_lexikon.py` liest die `<article class="lex-entry">`-Blöcke aus `index.html` und schreibt je Begriff `lexikon/<id>.html` (eigener Title/Description/Canonical, JSON-LD `DefinedTerm`, Links auf andere Begriffe und in die App, Vor/Zurück), die Übersicht `lexikon/index.html` und `sitemap.xml` neu. Läuft automatisch in `deploy-pages.yml` vor dem Upload; `lexikon/` ist deshalb in `.gitignore`, `sitemap.xml` ist eingecheckt, damit sie zum Deploy passt — nach Änderungen an Einträgen lokal `python3 scripts/build_lexikon.py` laufen lassen und `sitemap.xml` mit committen. Das Skript bricht ab, wenn es keine Einträge findet, ein Verweis ins Leere zeigt oder ein unbekanntes Link-Format auftaucht. Die ID `index` ist reserviert (würde die Übersicht überschreiben), deshalb heißt der Eintrag „Index" `aktienindex`.

**Musterdepot (`#depot-view`):** einfache Paper-Trading-Simulation. Startkapital `DEPOT_START_CASH` (10.000 €) plus vier fiktive Aktien (`DEPOT_STOCKS_DEFAULT`). „Kaufen“ investiert einen festen Betrag (`DEPOT_BUY_AMOUNT`, 500 €) zum aktuellen Kurs, „Verkaufen“ löst die komplette Position auf. Der komplette Depot-Zustand (Cash, Kurse, Positionen) wird als JSON unter `localStorage`-Key `boersenspiel_depot` persistiert, siehe `loadDepot()`/`saveDepot()`.

**Sparplan im Musterdepot (`.depot-plan-panel`):** Fiktiver „Welt-ETF" (`id: 'welt'`, in `DEPOT_STOCKS_DEFAULT`; `loadDepot()` ergänzt fehlende Standardwerte in älteren gespeicherten Depots). `depot.plan = {amount, month, paid}`; „⏩ 1 Monat"/„⏭️ 1 Jahr" ruft `simulateDepotMonths(n)` auf: pro Monat bewegen sich alle Kurse (`DEPOT_MONTH_MOVES`: ETF ruhig mit leichtem Aufwärtstrend, Einzelaktien stärker) und die Rate wird in den ETF investiert, sofern genug Cash da ist.

**Live-Modus im Depot:** „▶️ Simulation starten“ (`depotToggle`) startet `setInterval(tickDepotPrices, DEPOT_TICK_MS)` (1800ms) — Kurse bewegen sich automatisch per Random Walk, Kaufen/Verkaufen bleibt währenddessen über die normale Event-Delegation auf `#depotStocks` möglich (kein Re-Render blockiert Interaktion). `depotTrends` merkt sich pro Aktie die letzte Richtung (`up`/`down`) für die kurze Flash-Animation im Preis. „⏸ Pausieren“ oder Verlassen der Ansicht über `.back-btn` ruft `stopDepotLive()` auf, das den Timer beendet — sonst würde er unsichtbar im Hintergrund weiterlaufen. Beim Zurücksetzen des Depots wird der Timer ebenfalls gestoppt.

**Einnahmen — alles an EINER Stelle in `script.js` (Abschnitt „Einnahmen"):**
- `BROKERS`: **seit 2026-09-27 leer** — Max wollte die Broker-Werbung (Trade Republic, Scalable Capital) überall entfernen. Bei leerer Liste blenden `renderBrokerLinks()`/`renderBrokers()` alle `.broker-cta`-Kästen aus (Depot, Sparplan, Anbieter-Kasten im Broker-Bereich); der Broker-Bereich zeigt nur noch die Checkliste, das Impressum sagt „derzeit keine Werbung und keine Partnerlinks". Beim Wieder-Aktivieren das Impressum mitziehen. Aufbau eines Eintrags: Name, Link, Merkmale. Daraus erzeugt `renderBrokerLinks()` die Buttons in allen `.broker-cta-links[data-placement]` (Depot, Sparplan) und `renderBrokers()` die Karten im Broker-Vergleich (`#broker-view`). **Affiliate-Links nur hier eintragen**, sie gelten dann überall. GoatCounter-Events: `broker-<id>` (Depot), `broker-<id>-sparplan`, `broker-<id>-vergleich`. Im Broker-Vergleich stehen bewusst keine Gebührenzahlen (ändern sich oft; falsche Angaben auf einer Seite mit Partnerlinks wären wettbewerbsrechtlich riskant) — nur eine zeitlose Checkliste und der Verweis auf die Preisverzeichnisse.
- `SUPPORT_URL`: Ko-fi/Buy Me a Coffee/PayPal.me-Link. Leer = alle `.support-link`/`.support-box` bleiben versteckt (Footer, Erfolge-Seite). Datenschutz hat bereits einen Abschnitt „Unterstützen-Link".

Ist im Impressum unter "Werbung / Partnerlinks" offengelegt.

**KI-Berater (`#aiModal`, ausgelöst über `#aiAdvisorBtn` im Depot):** KEIN echter LLM-Aufruf — das ist bewusst so, weil diese App eine rein statische GitHub-Pages-Seite ohne Backend ist und ein API-Key eines LLM-Anbieters im öffentlichen Client-Code für jeden auslesbar/missbrauchbar wäre. Stattdessen wertet `generateDepotAdvice()` den tatsächlichen Depot-Zustand regelbasiert aus (Diversifikation über Anzahl gehaltener Aktien, Klumpenrisiko über den Anteil der größten Position am Depotwert, Cash-Quote, Rendite) und gibt daraus 3-4 passende, natürlich klingende Textbausteine zurück. `openAiAdvisor()` inszeniert das als Chat: erst eine "tippt..."-Bubble (`showTypingBubble`, ca. 1.1s), dann erscheinen die Nachrichten nacheinander leicht versetzt (450ms Abstand) als Sprechblasen. Der Disclaimer im Modal ("Regelbasierte Analyse... keine echte Anlageberatung") ist bewusst da, um nicht den Eindruck einer echten KI-Anlageberatung zu erwecken.

Die News-Ansicht hat ebenfalls ein KI-Element (Details im Abschnitt News): `renderNewsAiFazit()` erzeugt einen Ein-Zeiler über den 4 aktuell angezeigten Meldungen und berechnet ihn bei jedem `renderNews()`-Aufruf (inkl. "Weitere Meldungen") neu. Im Live-Modus ist das ein sachlicher "🤖 Überblick" (zählt steigende/sinkende Zahlen), im Beispielmodus das "🤖 KI-Fazit" (zählt bullish/bearish/neutral).

Beide KI-Features nutzen eine eigene Akzentfarbe (`--ai: #22d3ee`, cyan) statt der bestehenden Blau/Lila/Grün-Palette, damit "das ist der KI-Teil" auf den ersten Blick erkennbar ist (Badge, Button-Glow, Chat-Bubbles).

**Boot-Splash (`#bootSplash`):** Kurze "KI-System wird initialisiert..."-Animation (~1.3s) beim allerersten Laden der Seite pro Browser-Tab, passend zur AI/Tech-Optik. Zwei Mechanismen verhindern ein Aufblitzen bei wiederholten Ladevorgängen in derselben Session:

1. Ein **inline `<script>` direkt nach dem `#bootSplash`-Markup** (noch vor `bg-grid`/`bg-glow`) prüft synchron, BEVOR der Browser irgendetwas rendert, ob `sessionStorage['boersenspiel_booted']` gesetzt ist, und setzt in dem Fall sofort `display:none` — ohne diesen Trick gäbe es bei jedem Reload einen kurzen Frame, in dem der Splash unnötig aufblitzt.
2. `script.js` (ganz oben, vor allem anderen Code) liest denselben Zustand aus: nur beim allerersten Laden läuft die volle Sequenz (Timer, `hide`-Klasse für den Fade-out, danach `remove()`), bei jedem weiteren Laden in derselben Session wird das Element sofort ohne Animation entfernt.

Der Flag ist `sessionStorage`, nicht `localStorage` — der Splash soll bei jedem neuen Tab/Session-Start wieder einmal laufen, nicht nur beim allerersten Besuch überhaupt.

**PWA (Progressive Web App):** `manifest.json` (Name, Icons, `display: standalone`, Theme-Farbe) + `sw.js` (Service Worker) machen die App installierbar ("Zum Home-Bildschirm hinzufügen"/"App installieren") und offline-fähig. Der Service Worker (seit v10) arbeitet **network-first** für alles außer Schriftart/Icons/Bildern: online kommt immer sofort die aktuelle Version (Anfrage mit `cache: 'no-cache'`, also Nachfrage beim Server statt einer bis zu 10 Minuten alten Kopie aus dem Browser-Cache), offline die zuletzt geladene; Seitenaufrufe ohne Cache-Treffer bekommen offline die App-Shell. `fonts/`, `icons/` und `*.png/*.jpg/*.woff2` bleiben cache-first. Gecacht werden nur erfolgreiche Antworten (`response.ok`). Beim Installieren lädt der Service Worker die App-Shell mit `cache: 'reload'` am Browser-Cache vorbei. Hintergrund: Bis v9 war die App-Shell cache-first und `cache.addAll()` konnte veraltete Dateien aus dem 10-Minuten-HTTP-Cache von GitHub Pages übernehmen — die schon entfernte Broker-Werbung blieb dadurch bei Wiederkehrern sichtbar; außerdem cachte v7 und älter auch 404-Antworten (die Google-Bestätigungsdatei blieb im Browser eine 404). Registriert wird der Service Worker ganz am Ende von `script.js` nach `window.onload`. Bei jeder Änderung an den gecachten Dateien `CACHE_NAME` in `sw.js` hochzählen (aktuell `boersenspiel-v10`) — damit werden alte Caches beim nächsten Besuch gelöscht. Wer noch einen Service Worker bis v9 hat, sieht nach einem Deploy beim ersten Aufruf noch die alte Version (der alte Worker war cache-first); ab v10 genügt einmal Neuladen. Icons liegen unter `icons/icon-192.png` und `icons/icon-512.png` (plus `apple-touch-icon.png` für iOS und `favicon.png`) — alle aus einer einzigen 512×512-Canvas-Zeichnung (Gradient + 📈-Emoji) per `sips` auf die jeweilige Größe herunterskaliert, da auf der Maschine keine Bildbearbeitungstools (ImageMagick/Pillow) installiert sind. Das ist noch keine echte App-Store-Veröffentlichung, nur der PWA-Zwischenschritt dahin (siehe README).

**Social-Media-Vorschau:** `og-image.jpg` (1200×630, per Canvas gezeichnet und mit `sips` als JPEG statt PNG exportiert — deutlich kleinere Datei bei gleicher Bildqualität für einen Gradient-Hintergrund) wird über Open-Graph-/Twitter-Card-Meta-Tags in `index.html` eingebunden, damit geteilte Links (WhatsApp, Twitter/X, etc.) mit Bild + Beschreibung statt nacktem Link angezeigt werden. `og:image`/`og:url`/der `<link rel="canonical">` sind auf die GitHub-Pages-URL (`https://boersen-ratespiel.github.io/`) hartkodiert — falls die Seite unter einer anderen URL landet, müssen diese Tags angepasst werden.

**Deployment (GitHub Pages):** Veröffentlicht wird über `.github/workflows/deploy-pages.yml` (Settings → Pages → Source muss auf „GitHub Actions" stehen). Der Workflow läuft bei jedem Push auf `main`, manuell über Actions → "Deploy Pages" und als `workflow_call` aus `update-news.yml`. Hintergrund (bis 2026-09-27 lief die Seite über „Deploy from a branch"): Der klassische Pages-Build startet nur bei Pushes von Personen. Die stündlichen News-Commits mit dem `GITHUB_TOKEN` und Merges über GitHub-Apps (z. B. die Claude-App) lösten keinen Neubau aus — die Live-Seite stand dadurch vom 22.09. bis 27.09. still, inklusive fünf Tage alter News. Aus demselben Grund kann `update-news.yml` den Deploy nicht per Push anstoßen (GITHUB_TOKEN-Pushes starten keine anderen Workflows) und ruft ihn deshalb direkt auf. Vor dem Upload baut `deploy-pages.yml` die Lexikon-Seiten (`scripts/build_lexikon.py`). Nach dem Veröffentlichen meldet `scripts/indexnow.py` alle Adressen aus `sitemap.xml` per **IndexNow** an Bing, Yandex & Co. (nicht Google — das nimmt nicht teil). Als Nachweis dient die Schlüsseldatei `89b5c44daf64d11b88c1f15a5b345004.txt` im Root (Inhalt = Dateiname ohne `.txt`); **nicht löschen oder umbenennen**, sonst werden die Meldungen abgelehnt. Der Schritt läuft nur bei Push/manuellem Lauf (nicht bei den stündlichen News-Deploys) und mit `continue-on-error`, damit ein IndexNow-Fehler nie den Deploy rot macht. `deploy-pages.yml` checkt immer `ref: main` aus, sonst würde beim Aufruf aus der News-Action der Stand vor dem News-Commit veröffentlicht.

**TikTok (automatisch gepostete Foto-Beiträge):** `.github/workflows/tiktok-post.yml` läuft täglich um 15:41 UTC. Zuerst ruft er `deploy-pages.yml` auf, danach übergibt `scripts/tiktok_post.py` den Beitrag des Tages an die **TikTok Content Posting API** (Foto-Karussell, `media_type: PHOTO`). Die Bilder erzeugt `scripts/build_tiktok.py` bei **jedem** Deploy (Schritt mit `continue-on-error`): drei JPEGs in 1080×1920 plus `post.json` (Titel, Beschreibung mit `HASHTAGS`) unter `tiktok/<JJJJ-MM-TT>/`, gezeichnet per Canvas in `scripts/tiktok/render.html` und ausgeführt im Headless-Chrome, der auf den GitHub-Runnern schon installiert ist (kein Pillow, kein npm). Der Inhalt hängt nur vom Berliner Datum ab, deshalb liefern alle Deploys eines Tages dieselben Bilder. `tiktok/` steht in `.gitignore`, und es bleiben nur die letzten `KEEP_DAYS` Tage erhalten. Die Formate wechseln täglich (`KINDS`):
- „Rauf oder runter?": ein simulierter Kurs, im zweiten Bild die Auflösung. Es ist derselbe Generator wie bei der Tages-Challenge, aber mit eigenem Seed `tiktok|<datum>`, damit der Post nie die echte Challenge verrät.
- Quizfrage: kommt aus `QUIZ_DATA`, das als JS-Block direkt aus `script.js` übernommen wird.
- Börsen-Begriff: kommt aus den Lexikon-Einträgen und nutzt `parse_entries()` aus `build_lexikon.py`.

Inhalte werden also nur an ihren bisherigen Stellen gepflegt. **Keine Emojis in den Bildern**, weil auf dem Runner die Emoji-Schrift fehlt. Den oberen und unteren Rand frei lassen, weil TikTok dort Reiter und Beschreibung über das Bild legt. Lokal testen geht mit `python3 scripts/build_tiktok.py [datum] [chart|quiz|lexikon]`. Chrome muss dabei **ohne** eigenes `--user-data-dir` starten, sonst lädt es Komponenten nach und `--dump-dom` hängt.

TikTok holt Fotos nur selbst per URL ab (`PULL_FROM_URL`), und zwar nur von einem bestätigten URL-Präfix. **Einrichtung (einmalig, durch Max):**
1. Auf developers.tiktok.com eine App anlegen und die Produkte „Login Kit" und „Content Posting API" hinzufügen. Benötigt werden die Scopes `user.info.basic`, `video.upload` und `video.publish`. Als Redirect-URI `https://boersen-ratespiel.github.io/tiktok/` eintragen.
2. Unter „URL properties" das Präfix `https://boersen-ratespiel.github.io/` bestätigen. TikTok gibt dafür eine Signaturdatei vor, die ins Repo-Root kommt (wie die IndexNow-Datei: **nicht löschen**).
3. Die Secrets `TIKTOK_CLIENT_KEY` und `TIKTOK_CLIENT_SECRET` anlegen. Dann lokal `python3 scripts/tiktok_auth.py` ausführen und den ausgegebenen Wert als Secret `TIKTOK_REFRESH_TOKEN` speichern. Er gilt 365 Tage. Gibt TikTok einen neuen aus oder läuft er bald ab, warnt der Workflow.
4. Optional die Repository-Variablen `TIKTOK_POST_MODE` und `TIKTOK_PRIVACY` setzen:
   - `MEDIA_UPLOAD` (Standard): Der Beitrag landet als Entwurf im TikTok-Postfach. In der App kommen dann ein Sound dazu und man veröffentlicht von dort.
   - `DIRECT_POST`: TikTok veröffentlicht sofort. Solange TikTok die App nicht geprüft hat (Audit), sind nur private Beiträge (`SELF_ONLY`) möglich. Das Skript weicht dann automatisch darauf aus und warnt.

Fehlen die Secrets, endet der Workflow grün, ohne etwas zu posten. Ein erneuter manueller Lauf am selben Tag postet denselben Beitrag noch einmal (es gibt keine Doppel-Sperre). ## Achtung: lokaler Test-Server cached script.js

`python3 -m http.server` sendet keine `Cache-Control`-Header. Chrome cached `script.js` deshalb teils ohne jede Nachfrage (kein Log-Eintrag, kein 304) über mehrere Reloads hinweg, während `index.html`/`style.css` normal revalidiert werden. Wenn Änderungen an `script.js` im Preview nicht ankommen, obwohl die Datei auf der Platte korrekt ist: harter Reload reicht oft nicht — zur Sicherheit den Server auf einem neuen Port neu starten (neue Origin = garantiert kein Cache-Treffer).

**Noch wichtiger seit dem Service Worker (`sw.js`):** Sobald eine Origin (z. B. `http://localhost:8814`) einmal besucht wurde, registriert sich der Service Worker und cached `index.html` in der Cache Storage API. Ab dann liefert JEDER weitere Request auf diese Origin — auch `fetch(url, {cache: 'no-store'})` — die alte, gecachte Version aus, komplett unabhängig vom `python3 -m http.server`-Prozess und selbst wenn dieser Prozess neu gestartet wird. Ein `preview_start` mit demselben Port kann außerdem "reused: true" melden und einen alten, noch laufenden Prozess auf diesem Port weiterverwenden, statt die (evtl. geänderte) Port-Konfiguration aus `launch.json` neu zu lesen. Sicherster Weg beim Testen von Änderungen, die den Service Worker/die App-Shell betreffen: einen Port verwenden, der in dieser Session noch NIE besucht wurde (nicht nur "neu gestartet") — sonst testet man garantiert eine Cache-Leiche statt des aktuellen Codes.
